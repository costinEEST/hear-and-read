# Localization

- English is the first-visit default for both selectors, independently of the browser locale. An explicit `?lang=` selects page language; otherwise the optional remembered page preference is used. Normalize supported regional tags to their base language. Preserve other query parameters and the fragment. Back/Forward restores the URL language.
- Keep page language separate from practice language, saved session language, voice choice and source language. Loading a session or importing content must not change the page language. Legacy sessions without a language remain Hungarian.
- `languages.js` owns supported language metadata, allowed Wiki hosts and localized source examples, shared with the Worker through `languages.d.ts`. JW.org uses localized paths and Serbian script prefixes; `jwLanguage()` maps these to practice codes. Do not replace localized URLs with a language prefix alone.
- `locales/<code>.json` uses English UI messages as keys. Keep key coverage and interpolation slots identical across all dictionaries; `count.*` objects use locale plural rules. Dynamic UI assignments use `uiText`/`uiAttribute` bindings so language switching can update them without reconstructing controls. Update dictionaries when adding or changing UI text.
- Preserve reader word nodes, active speech, recordings, timing alignment, selected voices, focus, open dialogs and unsaved editor fields on page-language changes. Translate only UI messages; user text, titles, publisher names, voice identifiers and URLs are data. Never insert translation strings as HTML. Preserve literal substitution content, including dollar signs and braces.
- Set document language to the page language, reader/editor language to the practice language, and demo gloss language to the page language. `demos.js` owns authored parallel sentences; never generate translations of user content.
- Load and validate the next dictionary before applying it; ignore obsolete requests. Failed switches preserve the current interface and playback. Cache successful dictionaries and tolerate unavailable preference storage.
- Keep native select controls and mobile OS pickers. Use full-width stacked controls on narrow screens, visible labels, at least 48px touch targets, and check 320px reflow, 200% text and short landscape.
- `npm run test:browser-logic` covers dictionaries, substitution slots, plurals, locale races and sessions; Worker tests cover language-specific URL policies and extraction headings. Browser checks must also verify active playback, drafts, history and actual publisher examples. Fixture success does not prove live availability or audible quality.
- Add public modules and dictionaries to the explicit asset allowlist and Wrangler watch list. Client translations update metadata but do not create independently rendered SEO pages or justify hreflang alternates.
